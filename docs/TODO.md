## Известные ограничения
- Стриминговых русских моделей у sherpa-onnx нет: распознаём фразу целиком
  после остановки записи.
- В словаре модели нет цифр, поэтому числа нормализуются из слов пост-обработкой.
- Напоминания срабатывают, пока приложение запущено: планировщик живёт
  внутри приложения (проверка при старте и раз в 20 секунд). В Windows окно
  можно закрыть в трей, приложение продолжит работать; для запуска после
  входа в систему есть автозапуск с ключом `--hidden`.
- `sherpa_onnx 2.0.0` для Windows приходит без x64-DLL (только arm64),
  поэтому зафиксирована версия 1.13.8.
- Модели не в git: STT ~68 МБ в `assets/stt/sherpa/ru/`, TTS ~21 МБ
  в `assets/tts/sherpa/ru.zip`. Без них приложение соберётся, но голос
  не заработает.
- LLM-модель (~1 ГБ) тоже не в git и не в assets: ищется в
  `assets/models/` (dev), `<папка exe>/models/` или в support-dir.
  Без файла вкладка «Чат» покажет ошибку и кнопку «Указать путь к модели».
- **CPU без AVX2** (Sandy Bridge и старше, например i5-2500K): предсобранный
  `llamadart` плагин `ggml-cpu.dll` собран с AVX2 и не грузится — в чате будет
  «Модель не загружена». Лечение на этой машине:
  1. `tool\build_ggml_cpu.ps1` — собрать плагин из того же коммита llama.cpp
     (0.7.0) с `GGML_AVX2=OFF`, нужен Visual Studio с C++;
  2. `tool\patch_ggml_cpu.ps1` — подменить DLL в pub-кэше, кэше build-hook'а
     и сборках. Повторять после `flutter pub get`, обновления `llamadart` и
     `flutter build windows`.
  Готовый файл лежит в `native/win-x64/ggml-cpu.dll` (в git не попадает).
  Скорость на таком CPU: ~5 ток/с, короткий ответ — 3–5 с.
